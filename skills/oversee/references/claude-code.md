# Claude Code

- Workers: native `Agent` with `general-purpose` or a custom profile. `Explore` and `Plan` are host helpers, never workers. Use a non-fork agent: a fork runs on the parent's model and history, so it cannot be a cheaper named worker.
- Model: the per-call `model` takes an alias only (`sonnet`, `opus`, `haiku`, `fable`). A full model ID or `inherit` works only in profile frontmatter. When the user names an exact version no alias guarantees, use or create a project profile in `.claude/agents/` with the full ID, with the user's agreement. Edits to existing agent folders load within seconds; a newly created `agents` folder needs a session restart. Keep the profile out of the audited deliverable and name it in the report.
- Model precedence: per-call `model`, then profile `model`, then `CLAUDE_CODE_SUBAGENT_MODEL`, then the parent's. With `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` that variable wins and the call's model is ignored: report that instead of claiming the named worker.
- Effort: per-call `effort` (`low`, `medium`, `high`, `xhigh`, `max`, model-dependent) needs v2.1.292+ and overrides profile `effort`; `CLAUDE_CODE_EFFORT_LEVEL` overrides both. Resolve an unsupported setting; do not drop it. The user can confirm the model and effort a worker ran with in `/tasks`.
- Launch the batch as several `Agent` calls in one message. Limits: 20 concurrent, three nesting layers.
- Leave `isolation` and `name` unset, and use no profile with `isolation: worktree`: a worktree branches from the default branch, not the parent's `HEAD`, so its edits are not in the tree you audit; with agent teams enabled, a call with a `name` launches a teammate instead of a subagent.
- Waiting: where the `Agent` schema has `run_in_background` (`claude -p`, the Agent SDK, or fork mode off), set it to `false` on every call of the batch; the calls run together and the turn blocks until all return. Otherwise (interactive, fork mode on, the default) workers run in the background and each completion arrives as a notification in a later turn. There, as this host's exception to the no-text rule, end each waiting turn with only `Waiting for N workers.`: the host answers a turn with no text by asking for visible output. Arm no `ScheduleWakeup`, `Monitor`, no-op command, or loop as a fallback; completion notices resume you. A background wait in `-p` stops after `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS` of idle time (default 10 minutes; `0` waits indefinitely).
- A worker's permission prompt appears in the main session; a grant beyond one call applies to the whole session.
- You receive only a worker's final message. To retry, resume the finished worker with `SendMessage` to its agent ID; it keeps its history.
- Sandbox: started in a repository subfolder, `.git` can be outside the writable area, so `git stash create` fails; use the hash fallback.
- Headless `claude -p` workers: never add `--dangerously-skip-permissions` or `--permission-mode bypassPermissions` to keep them running.
- Plan mode: use the exit-plan tool for approval; otherwise the user cycles permission mode with Shift+Tab. Plan files live in `~/.claude/plans` unless `plansDirectory` is set, which may be outside what a worker can read. Verify execution is enabled before dispatch.
